# Dataset catalog

Every published lab runs offline. The course uses one small bundled dataset and a set of seeded synthetic generators, because a learner should not need an account, a download quota, or a GPU to finish a security exercise. This catalog records where each resource comes from, what its license or terms say, what it is good for, where it fails, and how to obtain it if you want to go beyond the labs.

Two rules come before everything else:

1. **Do not commit data.** Generated and downloaded data stay under `artifacts/` or `data/`, both excluded by `.gitignore`. Record a hash instead.
2. **Do not use personal or proprietary data.** The labs use public or synthetic records only. If you adapt a lab to a real dataset, do that outside this repository under an approved data-handling agreement.

The registry in [datasets/README.md](https://github.com/nadeem-majeedch/MLSec/blob/main/datasets/README.md) is the authoritative list of what each lab uses. This page is the reference catalog: provenance, licensing, limitations, and access.

## 2. Primary resource: scikit-learn digits

| Field | Detail |
|---|---|
| **Origin** | UCI Machine Learning Repository, *Optical Recognition of Handwritten Digits*. Bundled with scikit-learn as `sklearn.datasets.load_digits`. |
| **Contents** | 1,797 samples, 64 features (8×8 grayscale images, values 0–16), 10 classes (digits 0–9). |
| **License** | scikit-learn is distributed under the BSD-3-Clause license. The UCI dataset page for *Optical Recognition of Handwritten Digits* states CC BY 4.0 (verified 2026-10-28). Check both before redistributing the data outside a course installation. |
| **Intended educational use** | Evasion at small scale (LAB-03, LAB-04), poisoning curves (LAB-05), backdoors (LAB-08), membership inference (LAB-10), defense evaluation (LAB-11), API serving (LAB-14), monitoring (LAB-15), federated simulation (LAB-16). |
| **Strengths** | No download or account; deterministic; fast on a CPU; genuine image data rather than a toy function. |
| **Limitations** | Very small and low-resolution. Classes are comparatively easy to separate, so absolute attack success rates do not transfer to production vision systems. There is no official train/test split, so the split is part of your method and must be reported. Near-duplicates exist; a careless split can leak. It is not a benchmark for state-of-the-art robustness. |
| **Download** | None. Load it locally. |

```python
from sklearn.datasets import load_digits

digits = load_digits()
X, y = digits.data, digits.target   # X: (1797, 64), y: (1797,)
```

Record the scikit-learn version in your environment file. The pixel convention (values 0–16) matters if you rescale; state the scaling in your report.

## 3. Primary resource: synthetic fixtures

Synthetic data is the default for tabular, systems, and agent labs because it lets the lab define the attack surface precisely.

| Field | Detail |
|---|---|
| **Origin** | Generated by code in the lab package or `labs/shared/mlsec_labs/data.py`. |
| **License** | No third-party terms. The generator is part of this repository; the generated rows are yours to use for coursework. |
| **Intended educational use** | Controlled demonstrations where the ground truth is known: churn leakage (LAB-01B), Gaussian-mixture poisoning (LAB-06), tabular backdoors (LAB-07), extraction (LAB-09), dataset validation (LAB-12), supply-chain toy project (LAB-13), privacy utility (LAB-17), subgroup audit (LAB-18), RAG corpus (LAB-19), agent workspace (LAB-20). |
| **Strengths** | Deterministic under a seed; no privacy risk; small; the failure mode is designed rather than hoped for. |
| **Limitations** | Synthetic data encodes the designer's assumptions. A defense that works on a Gaussian mixture may fail on real, correlated, messy data. Results are evidence about the mechanism, not about a production distribution. Report the generator, seed, and parameters. |
| **Download** | None. Regenerate from the lab. |

A minimal deterministic generator, for reference only — the labs ship their own:

```python
import numpy as np

rng = np.random.default_rng(42)
X = rng.normal(size=(500, 10))
y = (X[:, 0] + 0.5 * X[:, 1] > 0).astype(int)
```

Every generator must be a pure function of its seed. If two runs with the same seed differ, the fixture is not reproducible and the lab result is not evidence.

Regenerate the documented fixtures with:

```bash
cd labs/lab-01b-evaluation-audit && python make_dataset.py --out artifacts
cd labs/lab-12-dataset-validation && python solution.py --out artifacts
cd labs/lab-13-supply-chain-audit && python solution.py --out artifacts
```

### 4.1 Getting started with the most useful optional sets

**UCI Adult.** Open the dataset page, choose *Download*, and unpack the archive. The file has no header row; the standard column names are documented on the page. Read it with `pandas.read_csv(..., header=None, names=columns, na_values="?")`. Do not treat the `sex` or `race` columns as ordinary features without discussing why they are there.

**SMS Spam Collection.** Download the archive from the UCI page and read the tab-separated file with `sep="\t"`, `header=None`, and names `label, message`. Check for duplicate messages before splitting; duplicates across train and test inflate accuracy.

**MNIST and Fashion-MNIST.** If you already use PyTorch:

```python
from torchvision.datasets import MNIST, FashionMNIST

train = MNIST(root="data", train=True, download=True)
test = MNIST(root="data", train=False, download=True)
```

The course does not require PyTorch. A NumPy or scikit-learn pipeline can use the same images after export, but record the export step and the exact version.

**CIFAR-10.** Download the Python version from the Toronto page and unpickle it with the loader described there. Treat the archive as untrusted input: unpickling arbitrary files is the risk described in [M10.2](modules/m10-supply-chain/lesson-2-unsafe-serialization-and-safe-formats.md). Use the official loader and verify the archive hash.

**FEMNIST.** Follow the LEAF site's instructions. The dataset is large and the preprocessing is nontrivial; for a course extension, use a small subset and document how you partitioned it. Client partitions are not interchangeable with random IID splits.

**EMBER.** Clone the repository and follow its README. Because no license file was found, do not redistribute the data or a derived feature file. If you need a shareable artifact, publish code and hashes, not rows.

**Credit-card fraud.** The Kaggle listing requires an account and acceptance of its terms. The OpenML mirror is labeled "Public" but is a mirror, not the licensor. Either way, do not attempt to re-identify records, and do not present the dataset as representative of any real institution.

**BackdoorBench.** The CC BY-NC 4.0 license permits non-commercial use with attribution. It is not suitable for a commercial course product or a paid cohort without separate permission. Check the license text, not this summary.

**AgentDojo, HarmBench, JailbreakBench, RobustBench.** Install from the project repository and pin the version. Benchmark content changes; a number without the benchmark version is not reproducible.

## 5. License rules of thumb

This is a summary for course planning, not legal advice. Read the actual license before redistributing anything.

| License or status | What it generally allows | What to watch |
|---|---|---|
| **CC BY 4.0** | Use, adaptation, and redistribution with attribution | Attribution must be preserved; check whether the source asks for a specific citation |
| **CC BY-NC 4.0** | Non-commercial use with attribution | "Non-commercial" is broader than "not sold"; do not assume a paid cohort is covered |
| **MIT / BSD-2 / BSD-3** | Permissive use and redistribution with the license notice | Keep the copyright and license text with redistributed code |
| **Site terms of use (UNB, TrojAI, Kaggle)** | Whatever the terms say, which may include registration, citation, or no-redistribution clauses | Terms change; record the date you checked |
| **No explicit license for the data (MNIST, CIFAR-10, EMBER)** | Unclear | Do not assert a license; do not redistribute; cite the source and ask the maintainer if you need permission |

Three practical consequences for this course:

- Lab artifacts may include **metrics and hashes**, not the data itself.
- Screenshots of a few examples are usually fine for teaching; redistributing a whole dataset is a different act.
- If a dataset's terms are unclear, choose a different dataset. The course's default is synthetic data for exactly this reason.

## 6. Integrity, versioning, and reproducibility

Record these for any dataset you use outside the bundled default:

| Field | Why it matters |
|---|---|
| Source URL and access date | The same page can serve different versions over time |
| Version or release tag | "CIFAR-10" is not a version; the archive is |
| SHA-256 of the downloaded archive | Lets a reader confirm they have the same bytes |
| Row or file count after extraction | Detects a partial download or a changed release |
| Preprocessing code and seed | The split and scaling are part of the result |
| License and citation | Required for ethical and legal reuse |

```bash
# Example: record a hash instead of committing the archive
sha256sum adult.zip > adult.zip.sha256
```

Store the hash in your run record or manifest, not the data. If a reader cannot obtain the dataset, they can still check whether your reported preprocessing is consistent with the hash you published.

If your capstone introduces a dataset, add a short card to your report. Sixteen rows are enough.

| Field | What to write |
|---|---|
| Name and version | The release or archive name, not just the family |
| Origin | Who created it, where it is hosted, and the canonical URL |
| License | The exact license or terms, with the date checked |
| Size | Rows, features, classes, and file size |
| Personal data | Whether any record is about a person, and how that was determined |
| Intended use | The task the dataset was built for |
| Your use | The task you are using it for; note any mismatch |
| Splits | How you split, whether the split is temporal or grouped, and why |
| Preprocessing | Cleaning, scaling, encoding, and deduplication |
| Labels | How labels were produced and what noise is known |
| Limitations | Sampling, coverage, label quality, and known artifacts |
| Leakage risks | Duplicates, group structure, temporal order, target leakage |
| Baseline | The result without your attack or defense |
| Ethics and safety | Why this data is appropriate for the exercise |
| Checksum | SHA-256 of the archive you used |
| Citation | The dataset's requested citation |

## 8. Pitfalls that invalidate lab results

- **Duplicate leakage.** Near-duplicate rows in both train and test inflate accuracy and can make membership inference look weaker or stronger than it is. Deduplicate before splitting.
- **Group leakage.** Images of the same object, messages from the same sender, or flows from the same host belong on one side of the split.
- **Temporal leakage.** A random split on time-ordered data trains on the future. Use a time-based split when the deployment is temporal.
- **Preprocessing fitted on the full data.** Scaling or feature selection before the split leaks test statistics into training.
- **Class imbalance ignored.** Accuracy is misleading when one class dominates. Report precision, recall, and the false-positive rate at the operating threshold.
- **Non-IID treated as IID.** Federated partitions are not random splits. LAB-16's client structure is part of the experiment.
- **Benchmark contamination.** For LLM benchmarks, the test items may appear in training data. Cite the benchmark version and note the risk.
- **Unstated version.** A dataset page that changed since your run makes your number unreproducible. Record the hash.
