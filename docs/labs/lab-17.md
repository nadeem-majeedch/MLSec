# LAB-17 — Privacy Budget, Noisy Release, and Utility

**Tier A · 4 hours · Difficulty 4 · Module M13 · Outcomes LO-19, LO-28**

## Why this lab exists

Differential privacy is often introduced as a library flag: add noise, report
epsilon, done. That framing hides the two decisions that make the claim
auditable. The first is the sensitivity of the statistic: how far one person's
data can move the output. The second is composition: how the budgets of several
releases add up. A release can be "noisy" and still have no meaningful guarantee
if either decision is wrong.

This lab implements a small Laplace mechanism directly, sweeps five privacy
budgets, and measures both utility and one empirical membership signal. The
reference result is intentionally unglamorous. Accuracy improves as epsilon
grows, but not monotonically at every step. The membership AUC stays near chance,
which is consistent with the mechanism but does not prove privacy. The formal
claim comes from sensitivity, the mechanism, and composition; the AUC is a sanity
check on one attack.

## The system and the threat model

| Element | Assumption |
|---|---|
| Asset | Whether a specific row was in the released dataset, and approximate feature values |
| Attacker goal | Membership inference or approximate reconstruction from the published summary |
| Attacker knowledge | The mechanism, epsilon, delta, sensitivity, feature count, and data distribution |
| Attacker capability | Observe one release and score rows by distance to the published centroids |
| Constraints | Two disjoint classes, 500 release rows per class, four features, one-shot release |
| Data | Synthetic two-class Gaussian data; 500 release, 150 test, and 150 nonmember rows per class |
| Metric | Nearest-centroid accuracy, mean centroid L2 error, distance-based membership AUC |
| Lifecycle stage | Data release and privacy accounting |
| Out of scope | DP-SGD, trained models, overlapping users, adaptive composition, reconstruction with auxiliary data, real personal data |

The data are synthetic and the release is a pair of class centroids, not a model.
The nonmembers come from the same generating distribution as members, which
makes the membership test hard by construction. That is realistic for a
well-designed release and also a limitation: a weaker baseline would make the
noise look more effective than it is.

## Safety rules

- Use only the synthetic Gaussian data generated by the lab.
- Do not apply the membership test to real people or real datasets.
- Do not present the AUC as proof of privacy, or its absence as proof of leakage.
- Do not tune epsilon after looking at the test accuracy and then report it as a pre-registered choice.

## Task specification

1. **Clip.** Clip every release and test feature to `[-3, 3]` without mutating
   the input array. Clipping bounds one row's influence and introduces bias; both
   facts belong in the report.
2. **Compute sensitivity.** For a class centroid over `n` clipped rows in `d`
   dimensions with bound `B`, changing one row moves the centroid vector by at
   most `2 * B * d / n` in L1. With `B=3`, `d=4`, and `n=500`, the sensitivity is
   0.048. Show the substitution, not just the number.
3. **Release with Laplace noise.** For each class, compute the clipped centroid
   and add independent Laplace noise to each coordinate with scale
   `sensitivity / epsilon`. Use a deterministic RNG seeded from the epsilon value
   so the run reproduces.
4. **Measure utility.** Classify each test row by the nearest noisy centroid and
   report accuracy. Report the mean L2 distance between each noisy centroid and
   its clipped, non-private counterpart.
5. **Measure one membership signal.** Score each row as the negative Euclidean
   distance to its class's noisy centroid. Stack member rows (label 1) and
   nonmember rows (label 0) and compute ROC AUC. A value near 0.5 means this
   particular attack found no useful signal.
6. **Sweep the budget.** Run epsilon at 0.02, 0.1, 0.5, 1.0, and 4.0 with delta
   0. Use the epsilon 0.5 release as the audit configuration.
7. **Account for composition.** The two class datasets are disjoint and fixed
   size, so parallel composition applies: the total budget equals the per-class
   epsilon, not twice it. State this assumption explicitly.
8. **Report the claim.** Name the mechanism, the statistic, the sensitivity, the
   composition rule, epsilon, delta, the data, and the measured utility. Then
   state what the empirical membership test does not establish.
9. **Check the artifacts.** Reproduce the table from a clean process and run the
   checker.

## Privacy measurement protocol

The order matters because it fixes what is being claimed:

1. **Choose the unit of privacy.** One row in one class dataset.
2. **Bound the data.** Clip to `[-3, 3]`.
3. **Derive sensitivity.** Compute `2 * B * d / n` for the centroid.
4. **Choose epsilon and delta.** Delta is 0 for the Laplace mechanism here.
5. **Release.** Add Laplace noise with scale `sensitivity / epsilon`.
6. **Account for composition.** Use parallel composition over disjoint classes.
7. **Measure utility on held-out rows.** Never evaluate on the release rows.
8. **Run one empirical attack.** Treat the result as a signal, not a proof.
9. **Document the scope.** Synthetic data, centroid release, one-shot query.

The non-private baseline is 0.8233. The clipped fraction of release rows is
0.0125, so clipping affects about 1.25% of values. The audit release is the
epsilon 0.5 row: Laplace mechanism, L1 sensitivity 0.048, parallel composition,
epsilon 0.5, delta 0, synthetic two-class data, nearest-centroid utility 0.7833.

Two features of the table are worth stating rather than smoothing over:

- Accuracy is not monotone at the top. Epsilon 4.0 gives 0.8167, slightly below
  epsilon 1.0 at 0.8233, even though the noise scale is smaller. The difference
  is 5 test rows out of 300. One noise draw and a small test set do not define a
  smooth curve.
- Membership AUC is near chance at every budget and is not monotone either. The
  values range from 0.4903 to 0.5308. This particular distance attack does not
  recover a stable membership signal in this setup.

## Threat-to-control mapping

| Threat | Evidence in the lab | Control tested | Residual risk |
|---|---|---|---|
| Membership inference | AUC 0.4903–0.5308 | Laplace noise and clipping | Near-chance AUC is not proof; adaptive attacks may do better |
| Approximate reconstruction | Centroid error falls as epsilon grows | Sensitivity-calibrated noise | Repeated releases compose and can accumulate signal |
| Overlapping users | Parallel composition assumes disjoint classes | Budget accounting | Overlap would require sequential composition |
| Utility collapse | Accuracy 0.5233 at epsilon 0.02 | Budget choice | A private release can be too noisy to be useful |
| Clipping bias | 1.25% of values are clipped | Bounded contribution | Truncation biases the estimate |
| Claim inflation | Report states mechanism and assumptions | Documentation | A written claim is not a formal verification |

## Defense-in-depth perspective

A privacy release has four independent obligations: bound the contribution,
calibrate the noise, account for every release, and measure utility on data that
was not used to choose the release. Secure aggregation, secure multiparty
computation, homomorphic encryption, and trusted execution environments can
change who sees the data during computation, but they do not by themselves bound
what the output reveals. Local differential privacy randomizes at the source and
avoids trusting the curator, at a substantial utility cost. Central differential
privacy gives a tighter bound but requires trusting the curator's process.

The layers fail differently. Clipping without noise bounds influence but does not
hide it. Noise without accounting cannot support a total budget. Accounting
without utility measurement produces a guarantee nobody can use. Utility
measurement without a threat model can miss the attack that matters. The lab
exercises all four, but only for a centroid release.

## How to check yourself

The checker rebuilds the synthetic data, recomputes the baseline accuracy and
sensitivity, validates every scale and delta, checks the direction of the utility
results, and checks the AUC band. It does not reproduce your noisy draws, because

numbers could pass. The report is where you show that you understand why the

## Reflection questions

1. Why is the sensitivity `2 * B * d / n` rather than `B * d / n`? Derive the
   factor of two from the neighboring-dataset definition.
2. What exactly does epsilon 0.5 promise, and to whom? State the neighboring
   relation and the release in the same sentence.
3. Why does parallel composition apply to disjoint fixed-size classes, and what
   changes if the same person appears in both classes?
4. Accuracy at epsilon 4.0 is slightly lower than at epsilon 1.0. Give two
   explanations that do not involve a bug.
5. The membership AUC is 0.5308 at epsilon 0.5. What can you conclude, and what
   can you not conclude?
6. What would a stronger membership attack need that the distance score does not
   use?
7. How would you extend the accounting if you released the same centroids every
   day for a week?
8. Why is a DP guarantee still meaningful when an empirical attack fails to
   detect anything?

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `NotImplementedError` | A TODO block is untouched | Implement `clip_features`, `release_centroids`, or `membership_auc` |
| Scale is 0.012 at epsilon 0.5 | Sensitivity divided twice or the wrong formula | Scale must be `0.048 / epsilon`, so 0.096 at epsilon 0.5 |
| Accuracy near 0.5 at every epsilon | Noise not divided by epsilon, or centroids not separated by class | Use `scale = sensitivity / epsilon` and compute one centroid per class |
| AUC below 0.45 or above 0.60 | Score sign reversed, or member/nonmember labels swapped | Score is negative distance; members are label 1 |
| Every release is identical | Epsilon is not used in the RNG seed or scale | Recompute both per epsilon |
| Sensitivity is 0.012 | Only one dimension or one-sided change counted | Use `2 * 3 * 4 / 500` |
| Audit row mismatch | Comparing floats by identity | Select the row whose epsilon equals 0.5 numerically |
| Checker rejects the report | Missing "not a proof" or "limitations" | State the empirical limit explicitly |
