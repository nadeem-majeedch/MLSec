# LAB-18 — Explanation Stability and Subgroup Audit

**Tier A · 4 hours · Difficulty 3 · Module M14 · Outcomes LO-31, LO-32, LO-28**

## Why this lab exists

An explanation and a fairness report are both claims about a model that the model
itself does not make. Each can be accurate, misleading, or unstable. A feature
attribution can look reasonable and still change when an input moves by a small
amount. A fairness metric can improve while another fairness metric gets worse,
and the improvement can come from a change nobody wanted.

This lab audits one synthetic logistic model in two ways. It compares a baseline
with a group-reweighted model on accuracy, subgroup error rates, demographic
parity, and equalized odds. It then compares two explanation methods,
gradient × input and occlusion, under small Gaussian input noise. The reference
result is a metric conflict: reweighting lowers the equalized-odds gap from
0.1231 to 0.0930 but raises the demographic-parity gap from 0.0013 to 0.0125 and
costs 1.39 points of accuracy. Explanation stability is moderate, not perfect: on
rows whose prediction is unchanged, the top feature still flips about 14–15% of
the time.

## The system and the threat model

| Element | Assumption |
|---|---|
| Asset | Model decisions, the explanations shown to users or auditors, and subgroup outcomes |
| Attacker goal | Preserve a prediction while changing its explanation, or hide a subgroup disparity behind an aggregate metric |
| Attacker knowledge | Model family, feature meanings, explanation method, and perturbation scale |
| Attacker capability | Perturb inputs within a small Gaussian radius and query predictions and explanations |
| Constraints | Synthetic data, linear logistic model, six features, one train/test split, isotropic noise sigma 0.25 |
| Data | 1,200 synthetic rows; 840 train and 360 test; group 0 is 60% and group 1 is 40% |
| Metric | Accuracy, TPR, FPR, selection rate, demographic parity, equalized odds, bootstrap intervals, Spearman, top-2 overlap, top-1 flip rate |
| Lifecycle stage | Evaluation, audit, and explanation delivery |
| Out of scope | Deep models, image explanations, real protected attributes, causal fairness, production decisions, measured explanation leakage or adversarial explanation manipulation |

The data are synthetic and the model is linear. That makes the arithmetic
checkable. It also limits what transfers: a linear model's attributions are
especially easy to compute and compare, and the fairness result depends on this
particular data-generating process.

## Safety rules

- Use only the synthetic data generated by the lab. Do not substitute real people or protected attributes.
- Do not use the results to make or justify decisions about individuals.
- Do not describe a fairness metric as a guarantee of fair treatment.
- Do not describe explanation stability as proof of explanation fidelity.
- Keep the perturbation small and local; this is an audit, not an attack on a deployed system.

## Task specification

1. **Fit the baseline.** Logistic regression with `max_iter=2000` and
   `random_state=42`, trained on the 840-row training split.
2. **Fit the reweighted model.** Use the same model and split, with sample weight
   `n / (2 * count(group))` for each training row, so each group contributes
   equally. Do not reweight the test set.
3. **Compute subgroup metrics.** For each group, report sample count, accuracy,
   true-positive rate, false-positive rate, and selection rate.
4. **Compute the gaps.** Demographic parity is the absolute difference in
   selection rates. Equalized odds is the maximum of the absolute TPR difference
   and the absolute FPR difference.
5. **Bootstrap the gaps.** Resample within each group with replacement, preserving
   group sizes, for 2,000 rounds. Report the 2.5th and 97.5th percentiles.
6. **Compute gradient × input.** For the linear model, this is `X * coef_`. It is
   a local, model-specific attribution.
7. **Compute occlusion.** For each feature, replace it with the baseline value
   0.0, recompute the positive-class probability, and subtract the result from
   the original probability. Return an array with the same shape as `X`.
8. **Measure stability.** For each test row, compute the original attribution.
   Add isotropic Gaussian noise with sigma 0.25, recompute the attribution, and
   record Spearman correlation and top-2 overlap. If the prediction is unchanged,
   record whether the top-1 feature changed. Report the means and the flip rate.
9. **Report the trade-off.** Compare both models, state which metric improved and
   which got worse, and explain what the intervals do and do not establish.

## Audit protocol

The order below prevents the metrics from being chosen after the results are
known:

1. **Fix the groups and metrics.** Use group 0/1, accuracy, TPR, FPR, selection
   rate, DP, and EO.
2. **Fit the baseline.** No fairness intervention.
3. **Fit the reweighted model.** Change only the sample weights.
4. **Compute point estimates.** Report every subgroup, not just the aggregate.
5. **Bootstrap.** Quantify sampling variability on this split.
6. **Choose two explanation methods.** Gradient × input and occlusion.
7. **Perturb and recompute.** Use one declared noise scale and top-k.
8. **Compare and scope.** State metric conflicts, interval overlap, and what
   stability does not establish.

| Comparison | Value |
|---|---:|
| Equalized odds, reweighted minus baseline | −0.0301 |
| Demographic parity, reweighted minus baseline | +0.0112 |

The equalized-odds gap shrinks because the FPR gap shrinks, not because the TPR
gap improves. Both FPRs rise, group 1's rises more, and the maximum gap falls
from 0.1231 to 0.0930. That is a real arithmetic improvement in one metric and a
real cost in another. It is not evidence that the model treats either group well.

## Threat-to-control mapping

| Threat | Evidence in the lab | Control tested | Residual risk |
|---|---|---|---|
| Hidden subgroup disparity | Group 1 TPR is 0.7000 versus 0.7349 | Subgroup table with TPR and FPR | Aggregate accuracy hides within-group harm |
| Metric shopping | DP improves while EO worsens, or vice versa | Report both pre-specified metrics | No single metric settles fairness |
| Small-sample overconfidence | EO interval [0.0408, 0.2373] | Stratified bootstrap | Intervals describe this split, not deployment |
| Explanation instability | Top feature flips 13.9–15.0% on preserved rows | Gaussian perturbation test | One noise scale and one model |
| Prediction-preserving explanation change | Flip rate is conditioned on unchanged prediction | Measure top-1 change explicitly | Does not model an adversary optimizing the explanation |
| Explanation leakage | Coefficients and queries can reveal model or data | Discussed, not measured | Coefficients are an extraction surface |
| Overclaiming stability | Spearman near 0.90 | Scoped report | Stability is not fidelity, fairness, or privacy |

## Defense-in-depth perspective

Fairness-aware training, subgroup auditing, explanation review, robustness
testing, and privacy accounting answer different questions. Reweighting changes
the training objective. A subgroup audit measures outcomes. An explanation
stability test measures sensitivity to input perturbation. A privacy evaluation
measures what the model or its explanations reveal about training rows. None of
these controls substitutes for another.

The layers also conflict. Reweighting can trade accuracy for one fairness metric
while worsening another. A more stable explanation can be a less faithful one.
A model that hides subgroup attributes may be less discriminatory in one metric
and less auditable in another. The lab is designed so that a single number never
looks like a complete verdict.

## How to check yourself

## Reflection questions

1. The baseline DP gap is 0.0013, but the EO gap is 0.1231. How can both be true
   at once, and which one would you show a regulator?
2. Reweighting lowers EO by raising both FPRs. Is that a fairness improvement?
   State the value judgment in your answer.
3. The EO intervals overlap. What can you claim about the improvement, and what
   would you need to claim more?
4. Mean Spearman is about 0.90, but the top feature flips in about 15% of
   prediction-preserved rows. Reconcile those two numbers.
5. Does stability establish that an explanation is faithful? Give a counterexample.
6. What could an adversary do to manipulate an explanation that isotropic
   Gaussian noise does not model?
7. Which fairness metric would you prioritize for a credit decision, and what
   would you disclose about the metrics you did not optimize?
8. What would you add to this audit before using the model in a real decision
   about people?

## Hints

1. Fit the baseline and reweighted models on the same split. Reweighting changes sample weights, not the evaluation rows.
2. Occlusion replaces one feature at a time with a baseline value and measures the prediction change. Keep the baseline fixed.
3. Stability compares attributions under repeated bounded noise. Use a rank correlation and top-k overlap, not a single example.
4. A smaller fairness gap on one metric can widen another. Report the trade-off instead of declaring one model fair.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `NotImplementedError` | A TODO block is untouched | Implement `fit_models`, `occlusion`, or `stability` |
| Reweighted model matches baseline | Weights are all ones | Use `n / (2 * count(group))` per row |
| DP gap does not match | Using accuracy instead of selection rate | DP uses positive prediction rates |
| EO gap does not match | Averaging TPR and FPR differences | EO is the maximum of the two absolute differences |
| Bootstrap interval is reversed | Percentiles swapped | Use 2.5 and 97.5 |
| Occlusion shape mismatch | Replacing a whole column across all rows | Copy `X` per feature and replace one column |
| Flip rate above 0.30 | Counting rows whose prediction changed | Condition on prediction-preserved rows only |
| Spearman is negative | Ranking appends instead of `argsort` ranks | Use the provided `ranks` helper |
| Report rejected | Missing a required phrase | Name DP, EO, stability, trade-off, and limitations |
